# Worldview Specification v1

A worldview is a portable `.md` file that shapes how Agent Cortex thinks. Drop it into any Cortex installation and it reconfigures the entire cognitive system — how it plans, builds, evaluates, resolves tension, and learns.

## Quick Start

1. Create a `.md` file following this spec
2. Place it in `~/.agent-cortex/worldviews/` or provide the path at startup
3. Select it when Cortex asks how to set up the worldview

## File Format

A worldview file uses the extension `.worldview.md` — e.g. `sculptor.worldview.md`. It is Markdown with YAML frontmatter, structured sections, and prose frames.

```
---
[frontmatter]
---

# preamble
[ontological framing]

# vocabulary
[seven vocabulary terms]

# consultation
[frame prose]

# evaluation
[frame prose]

... (25 frame sections total)
```

## Frontmatter

YAML block between `---` delimiters at the top of the file.

| Field | Required | Type | Description |
|-------|----------|------|-------------|
| `name` | yes | string | Unique identifier. Lowercase, no spaces. Used for selection and persistence. |
| `description` | yes | string | One-line human-readable description. Shown in the preset selection menu. |
| `version` | yes | integer | Schema version. Currently `1`. |
| `systemName` | no | string | What the system calls itself. Default: `Cortex`. |
| `entityName` | no | string | What the system calls the entity it serves. Default: `the Parsifal`. Include the article if appropriate ("the Explorer", "Taylor", "the Team"). |
| `generated` | no | boolean | `true` if this worldview was generated by the pipeline rather than hand-authored. Informational only. |

Example:
```yaml
---
name: sculptor
description: Remove what doesn't belong — subtractive epistemology
version: 1
systemName: Chisel
entityName: the Artisan
---
```

## Preamble

Section heading: `# preamble`

3-5 sentences that capture the ontological center of the worldview. This is the single highest-leverage surface — it is injected at the start of every LLM call across all cognitive acts. After reading the preamble, the LLM should think differently.

The preamble is not an explanation of the worldview. It is an installation of it. Write it as identity, not description.

**Good:** "In this system, work is removal. The artifact already exists inside the constraints — your job is to find it by removing everything that isn't it."

**Bad:** "This worldview uses a subtractive approach where we focus on removing unnecessary elements." (Describes rather than installs.)

The preamble should introduce the vocabulary naturally — the reader should encounter the terms (top unit, leaf unit, artifact) in context before seeing them defined in the vocabulary section.

## Vocabulary

Section heading: `# vocabulary`

Seven terms that become the system's working language. These flow into JSON schemas, decomposition output, prompts, and all level comparisons. They are protocol, not decoration.

Format: `- key: value` (one per line). Terms with singular/plural forms use `singular / plural`.

| Key | Description | Example (sculptor) |
|-----|-------------|-------------------|
| `topUnit` | High-level decomposition unit | `block / blocks` |
| `leafUnit` | Leaf-level executable unit | `cut / cuts` |
| `artifact` | Completed work product | `form / forms` |
| `decomposeVerb` | How decomposition is described | `decompose into revealing cuts` |
| `completeVerb` | How completion is described | `reveal` |
| `nodeNature` | What a node "is" — fills "each node is ___" | `material to be removed` |
| `semanticNodeDescription` | How nodes are described in wiring/affinity prompts | `blocks (possibility spaces) and cuts (precise removals)` |

**The vocabulary test:** Given the ontological metaphor, someone should be able to guess most of these terms. If the vocabulary surprises, it's probably wrong. If the vocabulary feels inevitable, it's right.

## Frames

25 sections, each a `# heading` followed by 1-3 paragraphs of prose. Each frame replaces the identity/orientation portion of a specific cognitive act's prompt. The structural portion (JSON schemas, score ranges, output constraints) stays in code and is appended automatically.

A frame answers three questions for its cognitive act:
1. **WHO** — who is the system when performing this act?
2. **HOW** — how does this worldview approach this kind of thinking?
3. **WHAT** — what matters, what to attend to, what "good" looks like?

### Required Frames

All frames are technically optional — missing frames fall back to the default worldview. But a worldview with missing frames is incomplete. A fully portable worldview should include all 25.

| Heading | Key | What it shapes |
|---------|-----|---------------|

### Frame headings

Use kebab-case for multi-word headings (`# path-reasoning`, `# inquiry-synthesis`, `# sense-manifest`, `# vision-synthesis`, `# sense-evaluation`). Single-word headings stay as-is (`# consultation`, `# evaluation`, etc.). The loader maps both kebab-case and camelCase.

### Writing frames

Each frame should be 1-3 paragraphs of dense, specific prose. Not instructions — identity. The frame should read like how this mind thinks about this kind of thinking.

**Good frame (evaluation, sculptor):**
"You are assessing precision. Did the cut reveal more of the form, or did it damage what should have been preserved? A form where every cut was precise — where nothing remains that shouldn't, and nothing was removed that should have stayed — scores high."

**Bad frame (evaluation, generic):**
"Evaluate the work for quality and completeness. Check if it meets the requirements." (No worldview. Any mind could have written this.)

**The frame test:** Read the frame without seeing which worldview it belongs to. Can you identify the worldview? If yes, the frame has real identity. If it could belong to any worldview, it's generic.

## Validation

A valid worldview file must:

1. Have YAML frontmatter with at least `name`, `description`, and `version`
2. Have a `# preamble` section with non-empty prose
3. Have a `# vocabulary` section with all 7 terms
4. Parse successfully through `loadWorldview()` — all sections recognized, vocabulary terms valid

A *complete* worldview additionally has all 25 frame sections.

To validate a worldview file:
```bash
npx tsx -e "
import { loadWorldview } from './src/util/worldview-loader.js';
const w = loadWorldview('./path/to/worldview.md');
console.log('Name:', w.name);
console.log('Frames:', Object.keys(w.frames).length, '/ 25');
"
```

## Installation

### Method 1: File drop
Copy the `.worldview.md` file to `~/.agent-cortex/worldviews/`. The system detects `*.worldview.md` files at startup.

### Method 2: Path reference
When Cortex offers worldview setup, choose "Upload" and provide the file path. The worldview is loaded from wherever it lives.

### Method 3: Preset registration
To make a worldview appear in the preset selection menu, add it to the `PRESETS` map in `src/worldview/generator.ts` and the `PRESET_WORLDVIEWS` map in `src/worldview/store.ts`, with a corresponding TypeScript constant in `src/types/worldview.ts`.

## Portability

A worldview `.md` file is fully portable between Cortex installations. It contains no absolute paths, no installation-specific configuration, and no references to external resources. Copy the file, and the worldview works.

The only dependency is schema compatibility — a `version: 1` worldview works with any Cortex that supports schema version 1. Future schema versions will document migration paths.

## Authoring Guide

### Starting from a metaphor

If you know the ontological center:

1. Write the preamble — install the metaphor in 3-5 sentences
2. Derive the vocabulary — what are the inevitable terms?
3. Write `consultation` and `evaluation` first — these reveal whether your worldview actually shapes thinking differently
4. Write `building` and `resolution` — these reveal your worldview's distinctive move
5. Write the remaining 21 frames, checking each against the frame test

### Starting from a purpose

If you know what the worldview is FOR but not what it IS:

1. Ask: what orientation of attention would serve this purpose?
2. Find the metaphor that produces that orientation
3. Follow the "starting from a metaphor" path

### Starting from nothing

Use the worldview generation conversation: choose "Create" at the worldview setup prompt. The system will co-explore your instincts and derive the worldview from the conversation.
